# Ownlish Web testing

This document describes how to run and organize tests in `apps/web`.
`ARCHITECTURE.md` defines FSD boundaries; `package.json`, `vitest.config.ts`,
and `playwright.config.ts` are the executable test configuration sources of
truth.

## Test layout

```text
app/
  **/*.test.tsx             # Route-adapter and framework component tests
src/
  **/*.test.ts              # Node unit tests, colocated with behavior
  **/*.test.tsx             # jsdom component tests, colocated with UI
scripts/
  **/*.test.mjs             # Tests for executable local quality scripts
e2e/
  <product-area>/*.e2e.ts  # Playwright user journeys
  fixtures/                 # Shared Playwright test composition
  helpers/                  # Non-UI E2E utilities
  pages/                    # Reusable page objects
```

Keep unit and component tests beside the FSD slice or route adapter they
verify. Browser journeys belong in `e2e/<product-area>`; see
[`e2e/README.md`](./e2e/README.md) for page-object and fixture conventions.

## Commands

Run these commands from `apps/web`:

| Command | Purpose |
| --- | --- |
| `pnpm test` | Run all Vitest unit and component tests. |
| `pnpm test:unit` | Run Node-based `*.test.ts` tests. |
| `pnpm test:component` | Run jsdom `*.test.tsx` tests. |
| `pnpm test:cov` | Run Vitest with coverage reports. |
| `pnpm test:e2e:install` | Install Playwright Chromium. |
| `pnpm test:e2e:db:up` | Start the isolated browser-E2E PostgreSQL database. |
| `pnpm test:e2e` | Build and run the Playwright suite with the sibling API. |
| `pnpm test:e2e:db:down` | Remove the isolated browser-E2E database. |
| `pnpm lint` | Run ESLint, FSD boundaries, and semantic-color checks. |
| `pnpm build` | Create a production build. |

## Browser E2E safety

Playwright starts production builds of both applications and uses the E2E
database configured by `E2E_DATABASE_URL` (default:
`localhost:5434/ownlish_e2e`). Start it with `pnpm test:e2e:db:up` before a
local run and remove it with `pnpm test:e2e:db:down` afterward. Do not point
`E2E_DATABASE_URL` at local development, staging, or production data.

## Lighthouse

Use `pnpm lighthouse` for public mobile routes and `pnpm lighthouse:desktop`
for public desktop routes after `pnpm build`. The corresponding `:summary` and
`:assert` commands read the reports generated by those runs.

Authenticated Lighthouse needs Chromium, the isolated E2E database, and a
locally running sibling API seeded with `pnpm lighthouse:seed` against that
same database. Set the Web API and catalog-root environment values to the local
servers before building, then run `pnpm lighthouse:authenticated` or
`pnpm lighthouse:authenticated:desktop`. These are performance checks, not a
replacement for Playwright user journeys.

## CI

Web CI runs Vitest, lint, build, Playwright, and separate Lighthouse jobs.
Coverage includes both `src` and root `app`, so route adapters stay visible.
Playwright reports, traces, video, and Lighthouse artifacts are retained by CI
for the configured retention period.
